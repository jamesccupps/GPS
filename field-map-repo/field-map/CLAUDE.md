# Field Map — working notes

A single-file offline field map for a 10-acre parcel on Hobart Road in Auburn,
Maine. Runs on an Android phone in the woods, with no signal, to find survey
monuments and record what is on the ground.

**The user is James Cupps** — facilities director, strong Python, builds BAS
tooling and homelab software. Assume technical fluency. Do not explain what
`git` is. Do explain surveying or geodesy reasoning, since that is the domain
where the non-obvious constraints live.

---

## Build

```bash
python3 scripts/build.py --check     # -> dist/field-map.html  (~521 KB)
```

Concatenates `src/` + `vendor/` + `data/parcel.geojson` into one self-contained
HTML file, and writes a copy into the add-on's static dir. `--check` verifies
there are no external load-time dependencies, the app payload parses, and the
lock markers survive.

**Edit `src/`, never `dist/`.** `dist/` is generated.

The **web build** has no npm, no bundler, no transpiler. That is deliberate: the
whole thing must boot from a single file with no network, and the dependency
surface should stay small enough to audit. The Capacitor wrapper under `native/`
is the one exception — it has a lockfile and CI runs `npm ci` — and it never
touches `src/`.

**The workflows live at the git repo root, not here**: `<repo>/.github/workflows/`,
two levels up. Both `cd` into this directory via `defaults.run.working-directory`.

| Path | |
|---|---|
| `src/app.js` | the app — 1,997 lines, section-banner numbered |
| `src/index.html` | DOM shell + build tokens |

## The three things that will bite you

### 1. Grid north, not true or magnetic

Every bearing the app displays is **grid** north in Maine West State Plane, so
it can be compared directly against the recorded deed. The phone's magnetometer
reads **magnetic**, which here is 14.55° W (WMM-2025, drifting +0.09°/yr).

`declination()` exists and is applied in compass-up mode. This was a real bug
once — 14.5° is 128 ft of error over 500 ft. If you touch orientation code,
re-verify it.

### 2. Distances must go through State Plane, never lat/lon

`gridVec()` projects both points to State Plane feet and works there. Do not
introduce haversine or naive degree math — it will disagree with the deed and
the errors will be small enough to miss.

`toSP()` is verified against the **nine** State Plane coordinates printed on the
recorded plan — 0.0098 ft mean residual, 0.0225 ft max — and reproduces the deed
line table to 0.03 ft. Quote both numbers wherever you quote either: a bare
"better than 0.01 ft" is true of the mean only, and that shape of claim is what
cost a previous session an afternoon. **Treat it as frozen.** If a test
of it ever fails, the bug is in the caller.

`fromSP()` is its inverse, added for staking. It is strictly additive — `toSP` is
untouched — and it is verified *by* round-tripping against `toSP`, not against
its own arithmetic: `fromSP(toSP(p))` reproduces `p` to 0.0005 ft across western
Maine (0.0007 ft across the whole Maine West zone), and applied to the nine State
Plane coordinates printed on the plan it lands 0.0099 ft mean from the plotted
corners, the same residual `toSP` produces.
If those two ever disagree, the round-trip test says so immediately.

That accuracy is only real because `kml_to_geojson.py` rounds to **7 dp**. It was
6 dp, which is ~0.4 ft and swamped `toSP` by an order of magnitude — the doc
claimed 0.01 ft while the shipped geometry delivered 0.11. Do not "optimise" that
back.

`kml_to_geojson.py` now pins `encoding="utf-8"` on both the read and the write,
for the same reason `build.py` does. Before that, a default run on Windows
decoded the KML's degree signs as cp1252 and rewrote every bearing in all 21
course and corner descriptions — 149,824 bytes instead of 149,698, silently, and
straight into the locked Pages build. Verified: a default run is now
byte-identical to a `PYTHONUTF8=1` one.

### 3. The parcel geometry is exact; its placement is not

The deed traverse closes at 1:238,800. What floats is where the whole shape sits
on the earth — roughly ±10–20 ft, because the surveyor fitted it to the road
centerline.

This is why the **Fit** tab exists: average on one found monument, and the whole
parcel translates rigidly to match. It is a translation-only fit by design. Do
not add rotation or scaling — the shape is right, and fitting rotation to a
single noisy GPS point would make it worse.

## Constraints that are not obvious

- **No localStorage for anything large.** Photos and tiles go in IndexedDB.
  localStorage holds only small state, and its quota failures surface a banner
  (they used to be swallowed, which silently lost a day of marks).
- **Nothing may block the first paint on a network call.** The app is used where
  there is no signal. Tiles are the only runtime fetch and they fall back to the
  IndexedDB cache.
- **`renderList()`-style full rebuilds must not run per GPS fix.** `renderList()`
  rebuilds the list DOM only when marks change; `updateNav()` patches the
  distance text in place, throttled to 900 ms by `scheduleNav()`. This was
  400 ms/fix at 250 marks before it was split. (There is no `paintMarks` — an
  earlier draft of this doc named a function that does not exist.)
- **Escape anything user- or import-supplied** before it reaches a Leaflet
  tooltip or popup. Imported GeoJSON is untrusted: `clean()` strips markup,
  and coordinates are range-checked.
- **Touch targets ≥ 44 px, inputs ≥ 16 px font.** It is used with cold hands.
  16 px specifically stops mobile browsers auto-zooming on focus.

## Two sync backends, one merge rule

`SY.backend` picks between them; `detectHass()` probes `GET api/health` on boot
and switches automatically when running inside the add-on.

**Home Assistant add-on** — zero config. Ingress means HA already authenticated
the request, so there is no token, no passphrase, no CORS. Data lands in
`/data/marks.json` and rides along in HA backups. `PUT /api/marks` merges
server-side too.

**GitHub Contents API** — one token. Owner and repo are read from the Pages URL.
Payload is AES-GCM encrypted before upload. Survives the Pi being down.

Merge rule, identical in both: newest `updated` wins per mark id; a delete
(tombstone, kept 90 days) only wins if it is newer than that mark's own last
edit. So editing a mark someone else deleted brings it back — finding a monument
should beat writing it off.

**Photos never sync.** They stay on the device that took them.

## Testing

No test suite. Verification is a browser driving the built file against a local
server, plus reading the code and checking numbers against the plan — the
findings in `docs/AUDIT.md` came from all three, not from a browser alone.

```bash
cd dist && python3 -m http.server 8777        # localhost is a secure context
```

Geolocation needs HTTPS or `localhost`. A `file://` load gets no permission
prompt at all — the app detects this and explains it rather than showing dashes.

Things worth asserting after any change: `toSP` against the nine plan corners
(0.0098 ft mean, 0.0225 ft max), `gridVec`/`quad` against the deed line table
(0.030 ft max), MGRS against `19T DJ 02895 72763` at 44.0016/-70.2112,
cross-track zero on a line and 20.00 ft at a 20 ft offset, `fromSP(toSP(p))`
round-tripping under 0.001 ft, staking the recorded Course 8 call from the
Course 7 corner landing within 0.03 ft of the recorded corner, and a soak of
~1,200 synthetic fixes watching per-fix cost and heap growth.

`native/scripts/bridge_harness.py` builds the one condition a browser cannot
supply: a Capacitor bridge that is present and throws on every call. Run it after
any change to `native.js`. The assertions that matter are that the tab wiring at
the end of `app.js` was reached, that `avg`/`PEEK`/`buzz`/`SY` are not in a
temporal dead zone, and that the status line carries no `uncaught:` — a truncated
`app.js` is the failure mode this wrapper produces, and it looks like anything
but a crash.

Two things the browser cannot show you, so do not read them as bugs:
`requestAnimationFrame` does not fire in a non-compositing pane, so the vector
canvas reads as blank until you force `canvasR._redraw()`; and `map.setZoom()`
never completes without rAF, so pass `{animate:false}` when driving it from a
test.

## How it ships

Two CI pipelines, both green and both required reading before you change a build
script.

**`.github/workflows/pages.yml`** → https://jamesccupps.github.io/GPS/
Builds, then `scripts/lock.py` encrypts the parcel into `_site/index.html` using
the `FIELDMAP_PASSPHRASE` repo secret, and publishes that plus `sw.js`, the
manifest and the icons. The unlocked build never leaves the runner. `lock.py`
refuses to write a file containing any `TELLTALES` string, so a leak fails the
deploy instead of reaching the internet — that guard exists because a comment in
`app.js` naming the road once shipped in the clear.

**`.github/workflows/apk.yml`** → https://github.com/jamesccupps/GPS/releases/latest/download/field-map.apk
Builds the APK on a runner and publishes it to a rolling `apk-latest` release, so
the phone has one permanent link. **The dev machine cannot build it**: Java NIO
cannot create a Selector there — `sun.nio.ch.PipeImpl`'s AF_UNIX self-connection
returns `EINVAL`, so every Gradle invocation dies with "Unable to establish
loopback connection" before compiling anything. Plain TCP loopback, `Pipe.open()`
and `SocketChannel` all work; it is an OS or endpoint-security problem on that
machine, not the project. **CI is therefore the feedback loop**, which is why the
workflow parses every Android XML before Gradle starts — a stray `--` inside an
XML comment cost a full round-trip once, and the log needs a sign-in to read.

`scripts/build.py` pins `encoding="utf-8"` and `newline="
"` on every read and
write. Windows defaults to cp1252, which cannot decode the box-drawing section
banners in `app.js`, and its newline translation would pad `dist/` with CRLF and
make the output differ by platform.

## Known gaps

- **No background tracking in the browser.** Android suspends the page when the
  screen sleeps. The APK fixes this with a foreground service; the Pages copy
  cannot, and holds the screen awake instead.
- **The APK cannot be updated in place.** CI signs every build with a fresh
  runner-generated debug key, so Android refuses the install and the only route
  is uninstall — which wipes every mark. `versionCode` is also pinned at 1 and
  never bumped. **Fix these together**: Capacitor clears a persisted web-content
  path only when versionCode changes, so a stable key without a version bump
  would let a stale downloaded bundle outrank a freshly installed APK.
- **No barometer in the browser.** No web API for it. The APK has one
  (`FieldSensors.java`), used for relative height only.
- **Tile cache has no eviction.** "Clear cache" is manual.
- **90 days offline** can resurrect deleted marks (tombstone expiry).
- **Photos and tiles are not mirrored** to app-private storage in the APK — only
  the small `fm_` keys are. They are IndexedDB blobs and would be tens of
  megabytes across the bridge on every save.
- **A WebView has no downloads.** `<a download>` is inert unless the host sets a
  `DownloadListener`, and Capacitor sets none, so every export was silent. In the
  APK `native.js` replaces `window.dl` and `FieldSensors.saveDownload` writes
  through MediaStore. Anything new that produces a file must go through `dl()`,
  not build its own anchor — that is exactly how the photo zip got missed.

## Where this could go

Roughly in order of value. See `docs/STATE.md` for what is decided, what is
blocked on James, and the exact commands.

1. **Stable signing key + versionCode.** Blocks everything else about the APK and
   currently costs a full data wipe on every update. Needs a keystore James
   generates; the passwords are his.
2. **Content OTA.** Capacitor 7 already ships the mechanism — the built-in
   `WebView` plugin's `setServerBasePath` swaps the served directory while
   keeping the `https://localhost` origin, so the bridge, `localStorage` and
   IndexedDB all survive. The whole app is one HTML file, so this covers nearly
   every change without a reinstall. Download must happen in Java: GitHub release
   assets send no CORS headers, so a WebView `fetch` dies at the first redirect.
   Rollback is `setServerAssetPath({path:'public'})`, not `setServerBasePath`.
3. **Re-occupation** — averaging the same monument on a second visit currently
   creates an unrelated second mark instead of comparing against the first.
4. **External GNSS** (SparkFun RTK Postcard over USB serial) for sub-metre. Needs
   the native wrapper, which now exists, and hardware that does not.
5. **Trilateration helper** — tape distances from control points, least-squares
   adjusted, for features under canopy where GNSS will not converge. Pairs with a
   Bluetooth laser rangefinder.
6. **LiDAR-derived contours** baked as an overlay, from Maine's statewide DEM.
7. **Photo sync** via the add-on — a storage-size decision, not a technical one.

Do not add a JS framework or a bundler. The single-file, no-build-step property
is what makes this survivable in the field.
